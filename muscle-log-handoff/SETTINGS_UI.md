# Muscle Log — 設定・データ管理画面 UI仕様

- 文書バージョン: 1.0
- 作成日: 2026-11-01
- 状態: **提案仕様**（画面デザインは初稿。ユーザーによる個別承認は未取得）
- 上位仕様: `SPEC.md`
- 参考デザイン: `settings-ui-reference.png`（装飾・配置の参考。**画像内の「テーマ」「データ初期化」「バックアップ完了」表示は未承認のため実装必須ではない**）
- 対象: iPhone Safari / PWA、GitHub Pages

## 1. 目的と優先順位

記録を失わないための**JSONバックアップと安全な復元**を最重要機能とする。利用者が「端末内の自動保存」と「ユーザー管理の実ファイル保存」を区別できること。iPhoneのファイル保存操作をアプリが無条件に完了確認できるかのような表現をしない。

ホーム・レポートと同じ白系カード・青の操作アクセント・日本語表示・3タブナビを使用する。

## 2. 画面構成（上から順）

1. ヘッダー: `Muscle Log` / `設定`。
2. **データの状態**: 端末内保存の状態（読み込み中／正常／失敗）、現在の記録件数、未バックアップ変更の有無、最終「ユーザー確認」日時。バックアップ未実施なら「未作成」表示。
3. **データ管理**: `JSONを書き出す`（主要アクション）、`JSONから復元する`（慎重に扱うアクション）。
4. **バックアップの案内**: 書き出し方法、ファイルの保存先（iPhone内・iCloud Drive等は利用者が選択）、復元時に既存記録が置き換わることを説明。
5. **バックアップのリマインド**: 7日経過＆未書き出し変更ありならアプリ内の控えめな注意を表示（暫定）。プッシュ通知なし。設定トグルの追加は初期必須ではない。
6. **アプリについて**: データ保管・プライバシー説明、利用方法、バージョン表示。
7. **PWAの利用案内**: ホーム画面への追加手順と注意点（必要な環境にのみ表示）。
8. 下部ナビ: `ホーム`／`レポート`／`設定`、Safe Area考慮。

`データの初期化`・`テーマ切替`はモックアップに描かれているが、ユーザー未承認なので**初期版では実装対象外**。今後採用する場合は別途明示的な仕様決定が必要。

## 3. 保存状態の定義

- `端末内に保存済み`: 最新の記録変更トランザクションがIndexedDBに正常コミットされ、未完了の保存がない状態。**JSONファイルの保存を意味しない**。
- `保存中`: トランザクション完了待ち。重複操作や終了を避ける案内を出してよい。
- `保存できませんでした`: IndexedDB書込みが失敗した状態。成功したように扱わず、再試行可能な案内を示す。
- `バックアップ未確認`: 書き出し後、ユーザーがファイルを保存したと確認していない状態。書き出し操作の開始だけで確認済みにしない。
- `未バックアップ変更あり`: 直近に確認済みのエクスポート時点のリビジョンより作業データのリビジョンが新しい状態。
- `バックアップ確認済み`: 利用者が保存を明示的に確認したときのリビジョンと日時が記録され、以後の変更がない状態。**アプリによる実ファイル検証済みという意味ではない**。

画面表示文言例: `端末内に保存済み`、`ファイルの保存は未確認です`、`バックアップ後に記録が変更されています`、`最終確認: 2026/11/01 12:00`。

## 4. JSONエクスポート

1. `JSONを書き出す`を押す。
2. 保存済みレコードとデータリビジョンを一貫したスナップショットとして読み出す。バリデーションに失敗した場合は書き出さず、エラーを表示。
3. UTF-8 JSONを生成。`version: 1`、`exportedAt`、`records`を含める。ファイル名は`muscle-log-YYYY-MM-DD-HHmmss.json`形式。
4. iOSで利用可能なダウンロード/共有の仕組みで、利用者のファイル保存操作を促す。Safariが特定の元ファイルを**自動上書きすることは要件ではない**。
5. 書き出し操作後、`ファイルを保存できましたか？` と確認する。`保存した`／`まだ・キャンセル`を選べる。
6. `保存した`を選んだ場合にのみ、**書き出し時点のリビジョン**と確認日時を管理情報に保存。確認待ち中に新しい記録が追加された場合は、未バックアップ変更ありを維持。
7. `まだ・キャンセル`の場合は確認済み日時を更新しない。失敗理由が分かれば日本語で通知する。

**技術上の注意**: ブラウザでは、ファイル保存先やファイルシステムへの実際の保存完了を必ず確認できるとは限らない。`ダウンロード開始`と`保存完了`は区別する。`navigator.share()`が使える場合の共有導線は任意、ブラウザのダウンロードを基本フォールバックとする。

## 5. JSONインポート・全件置換

1. `JSONから復元する`で`accept=".json,application/json"`のファイル選択を開く。利用者がキャンセルしたら変更なし。
2. 最大10MBのサイズ制限（暫定）を確認して、UTF-8 JSONとして読み込む。
3. JSON構造・`version`・ID一意性・実在日付・6部位コード・安全な正整数・ISO日時等、`SPEC.md`の全条件を**全件検証**する。異常が1件でもあれば復元拒否。現在の記録は変更しない。
4. 読込結果の確認画面で、`ファイル内の記録件数`、`最古・最新の運動日`、`現在の件数`、`置換後の件数`を表示。**既存記録が全件置き換わり、元に戻せない可能性がある**と明記する。
5. 既存データがある場合、先にバックアップすることを推奨する。ただし確認をした利用者の明示操作で置換を進められる。
6. `復元する`と`キャンセル`を設け、キャンセルでは何も書き換えない。確認後、IndexedDBの単一トランザクションで全件置換し、管理リビジョンを更新する。
7. 復元成功後、件数・集計・履歴を再読込。最終バックアップ確認日時を安易に更新せず、**未バックアップ変更あり**として扱う。
8. 復元失敗・容量不足・トランザクション失敗のいずれでも旧データを保持し、失敗を表示する。

初期版は**全件置換のみ**。既存データへの追記・マージ・競合解決は行わない。

## 6. リマインドと初回案内 [暫定]

- 最終バックアップ確認日から7日以上経過、かつそれ以降に変更があった場合、ホーム/設定に控えめなバナーを表示。
- 一度もバックアップ確認がない場合は、記録が存在すればバックアップ未作成と表示し、書き出しを案内（初回から強い警告を連発しない）。
- 毎回の即時加算の邪魔になるダイアログは表示しない。通知許可やOSプッシュ通知は使用しない。
- Safariとホーム画面版PWAでは記録データの保存領域が別々になる可能性があることをガイドに明示する。両方から同じデータが見えると保証しない。

## 7. PWA案内 [暫定]

- iPhone Safariの通常タブでは、共有メニューから「ホーム画面に追加」する操作を簡潔に紹介（OSバージョンによって文言・位置が変わり得る）。
- すでにホーム画面から起動している場合はインストール案内を抑制する。
- iOSで一般的なWebの`beforeinstallprompt`を前提としない。実際の案内はユーザー操作の手順とする。
- オフライン利用はService Workerの初回キャッシュが完了した後であることを説明する。

## 8. 画面状態・アクセシビリティ

- 保存・書き出し・検証・復元は処理中状態を明示し、重複実行を防ぐ。
- 破壊的操作は強調した警告と明示的確認を必要とする。確認ダイアログで内容が読めること。
- ファイルの不正内容を画面にそのままHTMLとして挿入しない。ファイル名の文字列も安全に表示する。
- データが0件でも空のJSONはエクスポート可能。インポートで0件の正常ファイルを選んだ場合も、0件への**全件置換**と明示して確認する。
- iPhone幅320/375/390/430pxと文字サイズ拡大で、ボタン・状態文言が切れず操作可能。
- VoiceOverを想定して各操作ボタン・状態ラベルをテキストで提供し、色・アイコンだけで結果を表現しない。
- 下部タブとOSのホームインジケータが重ならないようSafe Areaを確保する。

## 9. 検証シナリオ（受け入れ条件）

- [ ] IndexedDBの保存状態とJSONバックアップ状態が明確に区別される。
- [ ] 記録2件以上をJSONにエクスポートし、構造・値が正しいことを確認できる。
- [ ] 書き出し開始だけではバックアップ確認日時が更新されない。
- [ ] `保存した`を押すと対象スナップショットのリビジョンが記録される。
- [ ] 書き出し中または確認待ちに記録を更新したら未バックアップ表示が残る。
- [ ] 有効なJSONを読み込み、件数と対象期間を確認してから全件復元できる。
- [ ] 不正JSON、未対応バージョン、重複ID、不正回数、サイズ超過、キャンセル時に旧データが維持される。
- [ ] 置換トランザクションが途中失敗しても旧データが保持される。
- [ ] 復元後にホーム履歴・レポート値が一致して更新される。
- [ ] データのない状態や一度も書き出していない状態で、UIが破綻しない。
- [ ] PWA追加手順をiPhoneで確認でき、通常Safariと保存領域が異なる可能性の案内がある。
- [ ] 画面320px幅・拡大文字・VoiceOverで主要操作が可能。

## 10. Claude Codeへの実装指示

1. `SPEC.md`を正本として、`HOME_UI.md`・`REPORT_UI.md`と同じトーンの設定画面を実装する。
2. JSON生成・検証・保存/置換トランザクションのロジックはUIから分離する。
3. インポートは検証完了前や承認前に絶対にデータを置換しない。
4. iPhone Safariでファイル操作の限界をテストし、実際の保存完了を断言しない。
5. 画像内に描かれた未承認機能（全データ初期化、テーマ変更、リマインド設定トグル）は勝手に実装しない。
6. ファイル書き出し/復元の各段階と例外系をテストする。

> 本書はユーザー承認前の提案版。実装対象となるのは`SPEC.md`に規定された設定・データ管理機能を中心とし、デザイン画像の追加装飾は強制しない。
