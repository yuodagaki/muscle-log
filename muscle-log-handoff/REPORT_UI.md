# Muscle Log — レポート画面 UI仕様

- 文書バージョン: 1.0
- 状態: **画面デザイン・休息日を含む平均の算出方法は承認済み**（2026-11-01）
- 上位仕様: `SPEC.md`
- デザイン参考: `report-ui-reference.png`（画面構成の参考。ダミー数値・日付を実データとして使わない）
- 共通人体UI: `muscle-log-body-ui/BODY_UI.md` / 正面・背面SVG

## 1. 目的とデザイン

記録した運動の**積み重ね**と、身体の**6部位の偏り**、**運動を継続できている状況**を、iPhoneの縦画面で読み取りやすく表現する。評価・診断・運動を休んだことへの否定的な表示はしない。

ホーム画面の意匠を踏襲する: 明るい背景、白い角丸カード、控えめな境界線、青い操作アクセント、下部3タブ「ホーム／レポート／設定」。数値には単位（回・日・%）を明示し、色だけに依存しない。

## 2. 画面レイアウト（上から順）

1. **ヘッダー**: アプリ名「Muscle Log」および見出し「レポート」。
2. **集計期間切替**: `今週 | 今月 | 今年 | 全期間`。1つを選択し、直下に集計開始日〜終了日を明記。初期表示は`今週`（デザイン案に合わせた暫定仕様）。
3. **期間サマリー**: 3枚のカードで「合計回数」「運動した日数」「1日あたり平均」を表示。例: `1,280回`、`5日 / 7日`、`約183回/日`（サンプル）。平均は**休息日を含む期間内の全暦日数**で割る。
4. **部位のバランス**: 正面・背面の簡易男性人体図を並べる（狭幅では縮小または縦積み）。6部位の色と累計回数・期間全体に占める割合を表示。ヒートマップの濃淡は対象期間内の相対回数に対応する。
5. **推移グラフ**: 「日別／週別／月別」切替と棒グラフ。期間内の記録を選択した単位で合計。期間・単位の選択を独立させる。ラベルを省略しすぎず、値を確認できるようにする。
6. **部位別累計**: 胸・背中・肩・腕・腹・脚の6項目を横棒グラフで表示。回数を明示し、前述の人体図と数値を統一する。
7. **継続状況**: 運動実施日のカレンダー（選択期間に応じた表示）と運動日数・実施率。休息日は未記録として中立的に表示。将来日は実施率の分母に含めない。
8. **下部タブ**: ホーム／レポート／設定。iPhoneのSafe Areaを考慮し、コンテンツがタブの裏に隠れないようにする。

画面が長くなることを許容する。全カードを無理にファーストビューへ詰め込まず、縦スクロールで読めるようにする。

## 3. 期間・日付の厳密な定義

- 「今日」は端末の**ローカル暦日**（主な利用想定は日本）とする。`date`の比較にUTC変換の副作用を持ち込まない。
- `今週`: 当日を含む週の**月曜日から今日まで**（最大7日）。
- `今月`: 当月1日から今日まで。
- `今年`: 当年1月1日から今日まで。
- `全期間`: **全記録中の最も古い`date`から今日まで**。全記録が空の場合は「対象期間なし」とし、平均を0回/日として表示する（期間日数は0扱い）。
- 過去日に記録があっても、未来日への登録はMVPで禁止されているため終了日は原則今日となる。
- 期間の両端の日付を含める。日付またぎ（DSTを含む）を扱えるよう、日数はミリ秒差を固定24時間で割らず、暦日の加算によって求める。
- 運動実施日: 対象日に**有効な記録が1件以上**ある場合。1日に複数部位・複数記録があっても1日と数える。

## 4. 指標と計算式

| 指標 | 定義 | 表示 |
|---|---|---|
| 合計回数 | 選択期間内の全`records[].reps`の合計 | `1,280 回` |
| 運動した日数 | 期間内に記録がある異なる暦日の数 | `5 日 / 7 日`（分母＝期間内暦日数） |
| 1日あたり平均 | **期間内合計回数 ÷ 期間内の全暦日数**（休息日を含む） | `約183 回/日` |
| 運動実施率 | 運動した日数 ÷ 期間内の全暦日数 × 100 | `71.4%` |
| 部位別回数 | 期間内の部位ごとの回数合計 | `胸 320 回` |
| 部位別比率 | 部位別回数 ÷ 期間内全体の回数 × 100 | `胸 25%` |

**平均回数の確定ルール:** 運動した日だけで割らない。例えば7日間で月曜200回・水曜300回、その他5日が0回なら、合計500回、運動2日、**平均500÷7≒71.4回/日**。これを`250回/日`とは表示しない。

- UIの平均表示は端数を**四捨五入した整数**とし、必要に応じて`約`を付与（例: `約71回/日`）。元の集計値は丸めずに保持する。
- 運動実施率は小数第1位に四捨五入して表示する（例: `71.4%`）。
- 部位別比率は整数%で表示してよい。ただし個別丸めのため合計が100%と一致しない場合があることを許容する。
- 分母が0またはデータ未記録の場合、`NaN`、`Infinity`を表示しない。回数・運動日数は0とし、比率は「—」または0%で統一する。
- 期間全体の合計が0なら、比較・ヒートマップに「記録がありません」を表示する。
- 過去日への追加・履歴の編集・削除が行われたら全指標を再計算する。キャッシュ済みの累計値を保存データの正本にしない。

## 5. 人体ヒートマップ

- `body-front.svg`、`body-back.svg`をホーム画面と共有し、`chest/back/shoulders/arms/abs/legs`の6部位に統一する。左右の腕・肩・脚は一部位として集計。
- ホームとは異なり、レポートの人体図は**閲覧主体**。色と数値が対応する。必要なら部位タップで数値・比率の詳細を表示できるが、記録編集画面へ直接飛ばす機能は必須ではない。
- 0回は中立色、0回超は同一部位の基準色の薄い〜濃い色で量を表現し、選択期間内の最大部位を最も濃くする。絶対回数の閾値による健康評価はしない。
- 6部位の基準色は`BODY_UI.md`に準拠する。色の濃淡だけでは比較困難なため、必ず各部位の**ラベル・回数・割合**を併記する。
- 胸・腹は正面のみ、背中は背面のみ、肩・腕・脚は正面/背面の両方に表示。どちらの面でも同一部位の値・濃淡を使用する。
- 期間変更時に人体図・凡例・部位別横棒グラフが同時に更新される。

## 6. 推移グラフ

- 表示単位: `日別`、`週別`、`月別`。初期値は`日別`（暫定）。
- 日別: 各日付の合計。週別: 月曜始まりの各週の合計。月別: 暦月ごとの合計。
- 期間外のレコードを集計に混ぜない。期間の最初と最後の週・月は**期間内部分だけ**を集計する。
- 選択した期間の対象日には記録0日の棒を0として含める。空期間は空状態を表示。
- グラフは合計回数のみを初期必須とする。部位別系列切替はMVPの必須機能ではない。
- iPhone幅でラベルが混雑する場合は横スクロール、軸ラベル間引き、タップ時の詳細表示などで対応し、数値を隠したままにしない。
- `今週` × `月別` のように棒が1本しかない組み合わせも仕様上正しい。禁止しない。
- Rechartsの表示と集計ロジックは分離し、集計を純粋関数としてテスト可能にする。

## 7. 継続カレンダー

- 記録のある暦日は実施済み、記録がない日付は休息日/未記録として中立的に表示する。
- 今日より後の日は未来日として区別し、集計分母にも含めない。
- `今週`では当該週、`今月`では当月、`今年`では月単位の一覧・ヒートマップ等、`全期間`では年月単位の閲覧や集約表示を用いる。長期間の全日付を一度に描画しない。
- 日数と実施率は第4章の値を共有する。
- 連続運動日数（ストリーク）は初期必須ではない。未記録日や休息日に「失敗」「サボり」等の否定的文言を使わない。

## 8. 画面状態・レスポンシブ

- 幅320px、375px、390px、430pxを主要検証対象とする。画面全体の横スクロールは避け、各カードを適切に折り返す。
- 狭幅で3指標カードが読みづらい場合、2列＋1列または縦積みに変更する。
- 期間切替とグラフ単位切替は別の状態として保持する（例: `selectedPeriod` / `chartGranularity`）。
- 初回・0件では合計0回、運動日数0日、平均0回/日、各部位0回、空チャート/カレンダーを正常表示する。
- データ読み込み中／読み込み失敗をそれぞれ明示し、古い集計値を最新値として誤表示しない。
- iOSの文字サイズ拡大とSafe Areaを考慮。ボタンは十分なタップ領域を確保し、グラフ・人体図の意味をテキストでも説明する。

## 9. Claude Code向け受け入れ条件

- [ ] 既存ホーム画面と統一感のあるデザインでレポート画面を表示できる。
- [ ] `今週／今月／今年／全期間`を切り替えられ、対象開始日〜終了日を確認できる。
- [ ] 全期間は最古の記録日〜今日までを集計する（記録0件の場合は期間なし）。
- [ ] 合計回数・運動日数・1日あたり平均が表示される。
- [ ] **平均は休息日を含む全暦日数で割る**（7日・2運動日・合計500回 → 約71回/日）。
- [ ] 実施率も運動した日数／全暦日数で求める。
- [ ] 6部位の回数と割合が人体図・凡例・横棒グラフで一致する。
- [ ] 人体の正面・背面で同じ部位の値が一致し、色の濃淡が対象期間の回数に対応する。
- [ ] 日別・週別・月別の推移グラフを切り替えられる。週は月曜始まり。
- [ ] 期間の先頭・末尾が週／月の途中でも、期間外の数値を含まない。
- [ ] 継続カレンダーに記録日と休息日が表示され、未来日が分母に含まれない。
- [ ] 履歴の追加・編集・削除後にすべてのレポート値が更新される。
- [ ] 0件・長期記録・日付境界・うるう年・幅320pxでも表示と計算が破綻しない。

## 10. 決定状況と実装の優先順位

- **確定**: 6部位、期間4種、日/週/月推移、人体ヒートマップ、部位別累計、継続カレンダー、休息日込みの日平均、ホーム画面と統一したデザイン。
- **暫定**: レポート初期期間`今週`、推移初期単位`日別`、平均整数丸め、長期カレンダーの具体的なページングUI。
- **対象外**: 医療的な筋肉負荷の診断、運動不足警告、目標達成評価、AIによるトレーニング提案。

> `SPEC.md`が全体仕様の正本、本書はレポート画面の詳細。競合する記載があれば、ユーザーが承認済みの条件（特に**休息日込みの平均**）を優先して両文書を整合させる。
